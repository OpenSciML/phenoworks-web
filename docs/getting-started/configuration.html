Configuration

PhenoWorks is configured through environment variables and an optional public app configuration JSON file. The same configuration model supports the current local backend and the planned hosted backend direction.

The app is crop-agnostic by design. For a new crop, field campaign, or institutional deployment, keep the same web platform and change the public config JSON to customize the visible title, subtitle, logo, and color theme.

Database Settings​

PostgreSQL metadata settings are split so local scripts and deployment tools can override values independently:

export PHENOWORKS_DB_HOST="localhost"
export PHENOWORKS_DB_PORT="5432"
export PHENOWORKS_DB_NAME="phenoworks"
export PHENOWORKS_DB_USER="postgres"
export PHENOWORKS_DB_PASSWORD="postgres"
export PHENOWORKS_DB_ADMIN_DATABASE="postgres"

SQLite is no longer a supported runtime database. Use PostgreSQL for local and hosted deployments.

Data Directory​

export PHENOWORKS_DATA_DIR="$HOME/.phenoworks"

In Docker Compose, PHENOWORKS_DATA_DIR remains the in-container path /var/lib/phenoworks. The Mac folder mounted there is controlled separately:

export PHENOWORKS_DATA_DIR_HOST="./data"
# or
export PHENOWORKS_DATA_DIR_HOST="/Volumes/ExternalDrive/phenoworks-data"

PhenoWorks stores file-backed outputs in this structure:

~/.phenoworks/
  data/
    user_<user_id>/
      project_<project_id>/
        studies/
        datasets/
        pipelines/
        .staging/
  .tusd/
  blocks/
  config/
  logs/
  db/

Resumable upload staging defaults to .tusd/ under PHENOWORKS_DATA_DIR. Set the canonical PhenoWorks upload setting when you need a specific upload location:

export PHENOWORKS_TUSD_UPLOAD_DIR="$HOME/.phenoworks/.tusd"

TiTiler URLs​

PhenoWorks uses two TiTiler-related URLs because they are read by different parts of the system:

export PHENOWORKS_TITILER_BASE_URL="/api/titiler"
export PHENOWORKS_TITILER_COG_BASE_URL="http://api:9000/api"

PHENOWORKS_TITILER_BASE_URL is the browser-facing tile route. In Compose, the Next.js container proxies /api/titiler to PHENOWORKS_TITILER_INTERNAL_BASE_URL=http://titiler:8000.

PHENOWORKS_TITILER_COG_BASE_URL is the API URL embedded in generated COG tile metadata so TiTiler can fetch the source raster through PhenoWorks. Compose uses http://api:9000/api because TiTiler and the API share the same Docker network. When the backend runs on the host and only TiTiler runs in Docker, use http://host.docker.internal:9000/api instead.

Branding​

The settings default public app config file is themes/phenoworks.config.json. Override it with:

export PHENOWORKS_APP_CONFIG_FILE="/absolute/path/to/app-config.json"

The public config controls:

FieldPurpose
titleVisible application title in the shell.
subtitleShort workspace label beneath the title.
logoDefault icon or image logo.
theme.light / theme.darkMaterial UI palette tokens.

Example:

{
  "title": "PhenoWorks",
  "subtitle": "Crop Phenotyping Workspace",
  "theme": {
    "light": {
      "primary": { "main": "#2f7d5c" },
      "secondary": { "main": "#365f91" }
    }
  }
}

LgoPy Catalog and Vector Index​

LgoPy analysis modules are stored in the configured catalog directory:

export PHENOWORKS_ANALYSIS_BLOCK_CATALOG_DIR="$HOME/.phenoworks/blocks"

When PhenoWorks uses PostgreSQL, it automatically maps the active database settings into LGOPY_CATALOG_DB_* variables for the LgoPy catalog vector index. This keeps the semantic-search blocks table in the same database as the rest of the PhenoWorks metadata, which is useful when teams need searchable analytical methods across large catalogs of remote-sensing and phenotyping routines.

export PHENOWORKS_DB_HOST="localhost"
export PHENOWORKS_DB_PORT="5432"
export PHENOWORKS_DB_NAME="phenoworks"
export PHENOWORKS_DB_USER="postgres"
export PHENOWORKS_DB_PASSWORD="postgres"

Enable semantic search by setting a Gemini API key. Without this key, deterministic catalog search by name, metadata, tags, and category still works.

export GOOGLE_API_KEY="..."
export LGOPY_CATALOG_GEMINI_EMBEDDING_MODEL_ID="gemini-embedding-001"

Inspect the effective catalog and vector-index wiring:

phenoworks analysis-blocks config

Frontend API URL​

When running Next.js separately from FastAPI, point the frontend at the API:

export NEXT_PUBLIC_PHENOWORKS_API_BASE_URL="http://127.0.0.1:9000/api"
tip

Use make run-dev CONFIG_FILE=themes/phenoworks.config.json with GNU Make, or just CONFIG_FILE=themes/phenoworks.config.json run-dev with just, when you want to launch with the default public config file through a project task runner.
