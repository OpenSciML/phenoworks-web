Tutorial: Create an Iris Classifier Model and Block

Train a classifier, package it as a BentoML service, and create an LgoPy block that adds predictions to a CSV. This tutorial follows the Iris example and builds on Hello World.

The classifier uses four flower measurements in centimeters to predict setosa, versicolor, or virginica. You will create two packages:

PackageFile created by this tutorialPurpose
BentoML serviceiris/iris_classifier.zipContains the fitted pipeline and inference service.
LgoPy blockZIP printed by the block command, inside iris/dist/Finds iris.csv, calls the service, and returns a prediction table.

1. Prepare the project and data​

You need Python 3.11, uv, Git, and a terminal. Clone the examples and install their locked environment:

git clone https://github.com/OpenSciML/phenoworks-examples.git
cd phenoworks-examples
uv sync --locked

If you already cloned the repository, open that folder and run uv sync --locked. Run the commands below from the repository root unless a step says otherwise. Keep the committed uv.lock: it records the dependencies used by the examples.

Local development does not require a PhenoWorks server or API key. To publish and run the packages in PhenoWorks later, you need an account and help from a platform administrator.

If Hello World is still serving, stop it with Ctrl+C. Both examples use port 4000.

The iris/ folder contains the notebook, service, block, README, citation file, and a sample iris.csv. The CSV contains 150 flowers with 50 examples per species. The required input columns are:

sepal_length,sepal_width,petal_length,petal_width
5.1,3.5,1.4,0.2
7.0,3.2,4.7,1.4
6.3,3.3,6.0,2.5

All four values must be numeric, finite, and greater than zero. Keep the filename iris.csv: the block searches for that exact name. The built-in scikit-learn dataset used for training is available without a data download.

2. Train and evaluate the classifier​

Launch the supplied notebook:

uv run --locked jupyter lab iris/iris_model.ipynb

Use the project's Python environment and run every cell in order. Work through these stages before building the service:

  1. Configure the model store. The setup cell sets BENTOML_HOME to iris/.bentoml/ before importing BentoML. Keep that location: the build and serve scripts use the same store.
  2. Load and inspect the data. load_iris(as_frame=True) supplies the four measurements and numeric targets. Inspect missing values, feature ranges, class counts, and the plots. The species labels are excluded from the inputs.
  3. Reserve the test set. The notebook uses a stratified 80/20 split with seed 42: 120 training flowers and 30 test flowers.
  4. Compare candidate classifiers. Five-fold stratified cross-validation on training data compares logistic regression, nearest neighbors, a support vector machine, a decision tree, and a random forest. Scaling stays inside the pipelines. Mean validation accuracy ranks the candidates, with macro F1 breaking ties.
  5. Evaluate the selected classifier. Fit the winner on the training set and evaluate it once on the held-out test set. Inspect the classification report and confusion matrix. The test set does not select the model.
  6. Save and reload the fitted pipeline. Save the same evaluated estimator, its feature order, and species names. Confirm that reloading preserves every held-out prediction.
  7. Check one flower. The measurements 5.1, 3.5, 1.4, 0.2 should be classified as setosa.

The save-and-reload cell is:

iris/iris_model.ipynb (save and verify)
bento_model = bentoml.sklearn.save_model(
    "iris_classifier",
    model,
    metadata={
        "feature_names": features,
        "target_names": target_names,
        "selected_algorithm": model_name,
        "test_accuracy": float(test_accuracy),
        "random_state": RANDOM_STATE,
    },
)

loaded_model = bentoml.sklearn.load_model(bento_model.tag)
assert (loaded_model.predict(X_test) == test_predictions).all()
print(f"Saved and reloaded: {bento_model.tag}")

Keep the saved-model tag and the results from your own execution. The notebook contains a recorded example result, but the values printed by your current run are the evidence for your package. A small Iris test split does not establish accuracy on new field data. Predicting the full sample CSV later is an integration demonstration, since it contains the same flowers used here.

3. Create the inference service​

Save the following as iris/iris_service.py:

iris/iris_service.py
"""Serve the Iris classifier trained and saved by iris_model.ipynb."""

from typing import Annotated

import bentoml
import numpy as np
import pandas as pd
from bentoml.exceptions import BadInput
from bentoml.validators import DataframeSchema
from pydantic import BaseModel, Field

FEATURE_COLUMNS = ["sepal_length", "sepal_width", "petal_length", "petal_width"]

# Match the training environment so the saved scikit-learn pipeline is compatible.
inference_image = bentoml.images.Image(python_version="3.11", lock_python_packages=False) \
    .python_packages(
        "scikit-learn==1.9.1",
        "pandas==3.1.0",
        "numpy==2.4.6",
        "pydantic==2.13.5",
    )


class FlowerMeasurements(BaseModel):
    """Four positive flower measurements in centimeters used for prediction."""

    sepal_length: float = Field(gt=0, allow_inf_nan=False, description="Sepal length in cm")
    sepal_width: float = Field(gt=0, allow_inf_nan=False, description="Sepal width in cm")
    petal_length: float = Field(gt=0, allow_inf_nan=False, description="Petal length in cm")
    petal_width: float = Field(gt=0, allow_inf_nan=False, description="Petal width in cm")


@bentoml.service(name="iris_classifier", image=inference_image)
class IrisClassifierService:
    """Predict Iris species using the packaged preprocessing and classifier."""

    # BentoML bundles this saved model into the ZIP and makes it available on import.
    model = bentoml.models.BentoModel("iris_classifier:latest")

    def __init__(self) -> None:
        """Load the packaged model and its training feature and species names."""
        self.classifier = bentoml.sklearn.load_model(self.model)
        self.feature_names: list[str] = list(self.model.info.metadata["feature_names"])
        self.target_names: list[str] = list(self.model.info.metadata["target_names"])

    @bentoml.api
    def predict(self, measurements: FlowerMeasurements) -> dict[str, int | str]:
        """Classify one flower from four measurements in centimeters.

        Args:
            measurements: Validated sepal and petal lengths and widths.

        Returns:
            Integer class ID and the corresponding Iris species name.
        """
        return self._predict_measurements(pd.DataFrame([measurements.model_dump()]))[0]

    @bentoml.api
    def predict_batch(
        self,
        measurements: Annotated[
            pd.DataFrame,
            DataframeSchema(orient="records", columns=FEATURE_COLUMNS),
        ],
    ) -> list[dict[str, int | str]]:
        """Classify a batch of flowers with one model prediction call.

        Args:
            measurements: DataFrame with the four measurement columns in
                centimeters. JSON requests use a list of row objects.

        Returns:
            One class ID and species per flower, preserving input order.
            An empty batch returns an empty list.

        Raises:
            BadInput: If any measurement is missing, nonnumeric, nonfinite,
                or not positive.
        """
        return self._predict_measurements(measurements)

    def _predict_measurements(
        self, measurements: pd.DataFrame
    ) -> list[dict[str, int | str]]:
        """Run the shared inference logic without calling another API endpoint.

        Args:
            measurements: Flower measurements in input order.

        Returns:
            Ordered predictions, or an empty list for an empty batch.

        Raises:
            BadInput: If measurements are missing or not positive finite numbers.
        """
        if measurements.empty:
            return []
        try:
            frame = measurements[FEATURE_COLUMNS].astype(float)
        except (KeyError, TypeError, ValueError) as error:
            raise BadInput("Provide all four numeric flower measurements.") from error
        if not np.isfinite(frame.to_numpy()).all() or (frame <= 0).any().any():
            raise BadInput("Flower measurements must be positive finite numbers.")
        # Match the feature names and order recorded during training.
        frame.columns = self.feature_names
        return [
            {"class_id": int(class_id), "species": self.target_names[int(class_id)]}
            for class_id in self.classifier.predict(frame)
        ]

The service loads iris_classifier:latest from the local training store and exposes two endpoints:

EndpointInput inside measurementsOutput
predictOne object with the four measurement fieldsOne class_id and species object
predict_batchA list of measurement objectsOne prediction object per row, in order

The single-flower endpoint uses a Pydantic model. The batch endpoint uses a pandas DataFrame schema with orient="records", so its HTTP body contains a list of row objects. Shared inference code checks positive, finite measurements and restores the feature names and order recorded during training.

The pinned inference dependencies match this example's training environment. When changing the environment, keep training and serving dependencies aligned and repeat the save/reload and endpoint checks.

4. Build and export the model package​

Save the service declaration in iris/bentofile.yaml:

iris/bentofile.yaml
service: "iris_service:IrisClassifierService"
name: iris_classifier
labels:
  task: classification
  dataset: iris
  display_name: Iris Classifier
include:
  - "iris_service.py"
exclude:
  - ".bentoml/"
  - "__pycache__/"
  - "*.zip"

Build the Bento after the notebook has saved its model:

sh iris/build.sh

The script sets BENTOML_HOME to iris/.bentoml/, builds iris_classifier:0.1.0, and exports iris/iris_classifier.zip. BentoML includes the saved model referenced by BentoModel in the package. The source store itself is excluded from the source-file list.

The script replaces an existing Bento with the same 0.1.0 tag in that local store. The fitted model has its own generated version; the exported service version is 0.1.0. If you retrain several times, latest selects the newest saved model at build time. Record the selected tag, and use an explicit saved model version when you need to rebuild a particular training result.

5. Serve and test the model​

Start the service and keep the terminal open:

sh iris/serve.sh

In another terminal at the repository root, check one prediction:

curl --fail --show-error http://localhost:4000/predict \
  -H 'Content-Type: application/json' \
  -d '{"measurements":{"sepal_length":5.1,"sepal_width":3.5,"petal_length":1.4,"petal_width":0.2}}'

The expected response is:

{"class_id": 0, "species": "setosa"}

Then exercise the batch endpoint used by the block:

curl --fail --show-error http://localhost:4000/predict_batch \
  -H 'Content-Type: application/json' \
  -d '{"measurements":[{"sepal_length":5.1,"sepal_width":3.5,"petal_length":1.4,"petal_width":0.2},{"sepal_length":6.3,"sepal_width":3.3,"petal_length":6.0,"petal_width":2.5}]}'

Check that the response is a list with two prediction objects in the same order as the input rows. The repository's iris/iris.http has additional requests.

6. Create the dataset-level block​

Open iris/iris_block.py. PredictIris receives the whole dataset, searches its items for the first iris.csv, and reads that table. It sends only the four measurement columns to predict_batch, then appends the returned class IDs and species to the original table.

For the PhenoWorks run below, replace its extras declaration with:

extras = {
    "supported_inputs": ["none:csv"],
    "transform_scope": "dataset",
}

The minimal repository example uses an empty supported_inputs list. This tutorial declares none:csv to match a CSV uploaded without a sensor and help the catalog identify compatible data. Dataset scope still calls the block once with the dataset's items; the block must select the named CSV itself.

The block and packaging function are:

iris/iris_block.py (block and packaging)
"""Predict Iris species for rows in a dataset's iris.csv file."""

from pathlib import Path

import pandas as pd
from lgopy.core import Block, BlockContext, ModelReference
from lgopy.models import HttpModelResolver


class PredictIris(Block):
    """Find iris.csv in a dataset and predict the species of each flower.

    Args:
        model: Deployed Iris classifier reference resolved by the execution host.
        batch_size: Maximum number of CSV rows sent in each request.
    """

    name = "predict_iris"
    display_name = "Predict Iris Species"
    description = "Find iris.csv in a dataset and predict the species of each data batch."
    version = "0.1.0"
    authors = ["PhenoWorks Team"]
    categories = ["Examples", "Model Inference"]
    tags = ["phenoworks", "example", "iris", "classification", "csv", "model-reference"]
    extras = {"supported_inputs": ["none:csv"], "transform_scope": "dataset"}

    def __init__(self, model: ModelReference, batch_size: int = 100) -> None:
        """Select the Iris classifier.

        Args:
            model: Model reference resolved by the execution host.
            batch_size: Positive maximum number of rows per prediction request.

        Raises:
            ValueError: If batch_size is not positive.
        """
        super().__init__()
        if batch_size <= 0:
            raise ValueError("batch_size must be positive.")
        self.model = model
        self.batch_size = batch_size

    def call(self, context: BlockContext) -> pd.DataFrame:
        """Predict each row in the first iris.csv found in the dataset.

        Args:
            context: Dataset information and dataset_items, each with files
                grouped by data product (for example, "csv"). file_uri is the
                local readable path supplied by PhenoWorks for this call.
                CSV columns must be sepal_length, sepal_width, petal_length,
                and petal_width, with positive finite measurements in centimeters.

        Returns:
            Original CSV rows with predicted_class_id and predicted_species
            columns.

        Raises:
            KeyError: If required measurement columns are missing.
            ValueError: If a measurement is not numeric or the response count
                differs from the input batch size.
            OSError: If the matching CSV cannot be read.
            RuntimeError: If iris.csv is absent, the service rejects a measurement,
                or inference fails.
            TypeError: If the model response is not a list of JSON objects.
        """
        iris_file = next(
            (
                file
                for item in context.input["dataset_items"]
                for files in item["files"].values()
                for file in files
                if Path(file.get("relative_path") or file["file_uri"]).name == "iris.csv"
            ),
            None,
        )
        if iris_file is None:
            raise RuntimeError("No iris.csv file found in the dataset.")

        table = pd.read_csv(iris_file["file_uri"])
        columns = ["sepal_length", "sepal_width", "petal_length", "petal_width"]
        class_ids: list[int] = []
        species: list[str] = []
        measurements = table[columns].astype(float)
        for start in range(0, len(measurements), self.batch_size):
            # DataframeSchema(orient="records") accepts JSON row objects.
            batch = measurements.iloc[start:start + self.batch_size].to_dict(orient="records")
            response = self.models.invoke(
                self.model,
                "predict_batch",
                json={"measurements": batch},
            )
            response.raise_for_status()
            predictions = response.json()
            if not isinstance(predictions, list) or any(
                not isinstance(prediction, dict) for prediction in predictions
            ):
                raise TypeError("The Iris model response must be a list of JSON objects.")
            if len(predictions) != len(batch):
                raise ValueError("The Iris model must return one prediction per input row.")
            class_ids.extend(prediction["class_id"] for prediction in predictions)
            species.extend(prediction["species"] for prediction in predictions)

        table["predicted_class_id"] = class_ids
        table["predicted_species"] = species
        return table


def generate_zip() -> Path:
    """Build the block with its README and citation into dist.zip.

    Returns:
        Path to the generated block ZIP archive.
    """
    root = Path(__file__).parent
    result = PredictIris.build(
        output_dir=root / "dist",
        format="zip",
        readme_file=root / "README.md",
        citation_file=root / "CITATION.cff",
    )
    return Path(result.archive_path)

The filename check uses relative_path when available and falls back to file_uri. Only the first matching CSV is processed. For the local example, file_uri is a readable local path; PhenoWorks prepares file paths at execution time for hosted runs.

The default batch_size=100 limits rows in each HTTP request. It is separate from PhenoWorks pipeline item batching. Missing columns, unreadable files, invalid measurements, and malformed model responses remain visible errors. The current implementation raises RuntimeError if no iris.csv is found.

7. Test the complete block and build its ZIP​

Keep the repository's main() and entry point below the code above. It maps iris_classifier:latest to http://localhost:4000, creates a BlockContext with one CSV record, and invokes the block with batch_size=2 to exercise multiple requests.

The input is organized as:

{
    "dataset_items": [
        {
            "files": {
                "csv": [
                    {
                        "id": 1,
                        "data_product": "csv",
                        "metadata": {},
                        "relative_path": "iris.csv",
                        "file_uri": "/absolute/path/to/phenoworks-examples/iris/iris.csv",
                    }
                ]
            }
        }
    ]
}

The existing test computes the absolute path from the script's directory, so you do not need to paste or edit that placeholder. With the model still serving, run:

uv run --locked python iris/iris_block.py

Check the printed preview for predicted_class_id and predicted_species. For the supplied CSV, the script should print Predicted 150 flowers. and then the ZIP path inside iris/dist/. It prints the first five rows rather than saving a local prediction CSV. The model ZIP remains at iris/iris_classifier.zip.

The packaging function includes iris/README.md and iris/CITATION.cff. Update those files for your own method before sharing a modified package.

8. Publish the model and block​

An administrator completes these steps:

  1. Open Models → Upload model and upload iris/iris_classifier.zip.
  2. Wait for successful package validation and inspect its log if validation fails.
  3. Choose Deploy model from the package menu and confirm Deploy. Follow the deployment until it is available.
  4. Open Modules → Publish module and upload the block ZIP printed in step 7.

If you are not an administrator, provide both archives to your platform administrator. After deployment, use the actual model_ref shown in Models or its How to use dialog. A local tag such as iris_classifier:latest is not the platform reference. A platform reference may look like model-4/iris_classifier:0.1.0; copy your instance's value rather than guessing it.

9. Run predictions in PhenoWorks​

  1. Create a dataset for this example.
  2. Upload iris/iris.csv as a single file with data product csv and modality none. Preserve the filename iris.csv and include only one matching CSV in the dataset for this exercise.
  3. In Modules, find Predict Iris Species and install it in your account.
  4. In Editor, right-click the dataset and choose Run Analysis. Select Predict Iris Species and continue to its parameters.
  5. Set model by selecting the available Iris deployment. Leave batch_size at 100 for this run; 150 rows then require two model requests.
  6. Review and start the run. Follow its status on Jobs and inspect the log if it fails.
  7. After completion, open View artifacts and inspect the results table. It should retain the original CSV columns and add predicted_class_id and predicted_species, with one row per input flower.

The block returns a DataFrame; PhenoWorks persists tabular results for the run. It does not need to save a separate artifact inside call. Download the table and compare a few rows with the CSV to confirm row order and measurement values. Do not treat predictions on this training-dataset example as an independent accuracy evaluation.

PhenoWorks injects the authenticated model resolver during the run. You can stop the local BentoML service with Ctrl+C once local testing is complete; the platform uses its own deployment.

Troubleshooting​

SymptomCheck
The build cannot find iris_classifier:latestRun every notebook cell through model saving. Keep the notebook, build, and serve scripts on the same iris/.bentoml/ store.
Port 4000 is already in useStop Hello World or an earlier Iris server before serving this model.
No iris.csv file found in the datasetKeep the exact filename and confirm the run includes that file.
Missing-column or numeric-conversion errorUse all four required column names and numeric measurements in centimeters.
The model rejects a batchCheck for zero, negative, infinite, or missing measurements.
The module is absent from the pickerRebuild and publish with supported_inputs set to ["none:csv"], install the module, and use a matching dataset.
No Iris service is offered for modelConfirm an administrator deployed the package and that it is available.
