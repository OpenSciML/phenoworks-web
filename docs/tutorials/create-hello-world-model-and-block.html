Tutorial: Create a Hello World Model and Block

Build your first model-backed analysis using the Hello World example. You will create a BentoML service, call it over HTTP, connect it to an LgoPy block, and package both for PhenoWorks. The service returns a greeting; it needs no training data or learned weights.

A model service exposes an inference endpoint. An analysis block selects inputs from a dataset and calls that service. Each has its own ZIP archive:

PackageFile created by this tutorialInstalled through
BentoML servicehello_world/hello_world.zipModels
LgoPy blockZIP printed by the block command, inside hello_world/dist/Modules

1. Prepare the example project​

You need Python 3.11, uv, Git, and a terminal. Clone the examples and install their locked environment:

git clone https://github.com/OpenSciML/phenoworks-examples.git
cd phenoworks-examples
uv sync --locked

If you already cloned the repository, open that folder and run uv sync --locked. Run the commands below from the repository root unless a step says otherwise. Keep the committed uv.lock: it records the dependencies used by the examples.

Local development does not require a PhenoWorks server or API key. To publish and run the packages in PhenoWorks later, you need an account and help from a platform administrator.

The hello_world/ folder already contains the working files. Open them in your editor and follow each step to understand and recreate their contents. Keep README.md and CITATION.cff alongside the block: its packaging function includes them in the module ZIP.

2. Create the greeting service​

Save the following as hello_world/hello_world.py:

hello_world/hello_world.py
from typing import Any

import bentoml


my_image = bentoml.images.Image(python_version="3.11") \
            .python_packages("xgboost", "scikit-learn")

@bentoml.service(
    name="hello_world",
    image=my_image,
)
class HelloWorldService:
    """A minimal greeting service."""

    @bentoml.api
    def greet(self, name: str = "World", context: dict[str, Any] | None = None) -> str:
        """Return a greeting with optional PhenoWorks execution context.

        Args:
            name: Name to include in the greeting.
            context: JSON execution input and previous outputs, accepted for
                model extensions and unused by this minimal greeting.

        Returns:
            Greeting for the supplied name.
        """
        return f"Hello, {name}!"

@bentoml.service declares the service and its Python image. @bentoml.api exposes greet as an HTTP endpoint. Sending {"name": "example.png"} produces Hello, example.png!; omitting name uses World.

The optional context argument accepts execution context for future extensions; this greeting does not use it. The image definition follows the example, including its declared Python packages.

3. Describe and build the model package​

Save the service entry point in hello_world/bentofile.yaml:

hello_world/bentofile.yaml
service: "hello_world:HelloWorldService" # module:class
name: hello_world
labels:
  owner: haruiz
  task: Test
  display_name: Hellow world
include:
  - "hello_world.py"

The service value is module:class: BentoML imports HelloWorldService from hello_world.py. include lists the service source to package. The labels provide example catalog metadata; replace the owner and display name for your own contribution.

Build and export the service:

sh hello_world/build.sh

The script changes into hello_world/, builds hello_world:0.1.0, and exports hello_world/hello_world.zip. It replaces an existing Bento with that same tag in your default BentoML store. Use a new version for a distinct release.

4. Serve the model and check its endpoint​

Start the service and leave this terminal running:

sh hello_world/serve.sh

Wait for BentoML to report that it is serving on port 4000. In a second terminal at the repository root, send a request:

curl --fail --show-error http://localhost:4000/greet \
  -H 'Content-Type: application/json' \
  -d '{"name":"example.png"}'

The response contains Hello, example.png!. This checks the service on its own before you connect it to a block. The Hello World and Iris services both use port 4000, so run only one at a time.

5. Create the LgoPy block​

Open hello_world/hello_world_block.py. The example's HelloWorldFile class inherits from Block and accepts a ModelReference parameter. Its call method reads the first filename from the item's files dictionary, invokes greet, and returns the response text.

For this tutorial's PhenoWorks run, use an RGB image as input. Replace the class's extras declaration with:

extras = {
    "supported_inputs": ["rgb:image"],
    "transform_scope": "dataset_item",
}

The repository's minimal example declares an empty supported_inputs list. The explicit pair above describes the files you will upload and lets the catalog and analysis picker match the block to RGB images. This block only reads a filename; it does not open or analyze image pixels.

The main parts of the block are:

hello_world/hello_world_block.py (block and packaging)
from pathlib import Path

from lgopy.core import Block, BlockContext, ModelReference
from lgopy.models import HttpModelResolver


class HelloWorldFile(Block):
    """Request greetings from a Hello World model.

    Args:
        model: Deployed Hello World model reference.
    """

    name = "hello_world"
    display_name = "Hello World"
    description = "Greet the first input filename using the Hello World model."
    version = "0.1.0"
    authors = ["PhenoWorks Team"]
    categories = ["Examples", "Model Inference"]
    tags = ["phenoworks", "example", "hello-world", "model-reference"]
    extras = {
        "supported_inputs": ["rgb:image"],
        "transform_scope": "dataset_item"
    }

    def __init__(self, model: ModelReference) -> None:
        """Select the model.

        Args:
            model: Model reference resolved by the execution host.
        """
        super().__init__()
        self.model = model

    def call(self, context: BlockContext) -> str:
        """Greet the first file, assuming an item without a plot.

        Args:
            context: Item containing one file grouped by type in ``input["files"]``.

        Returns:
            Greeting text returned by the model.

        Raises:
            RuntimeError: If the model returns an unsuccessful response.
            StopIteration: If the item contains no files.
        """
        file = next(file for files in context.input["files"].values() for file in files)
        filename = Path(file.get("relative_path") or file["file_uri"]).name
        response = self.models.invoke(self.model, "greet", json={"name": filename})
        response.raise_for_status()
        return response.content.decode("utf-8")


def generate_zip() -> Path:
    """Build the block with the root README and citation into dist.zip.

    Returns:
        Path to the generated ZIP archive.
    """
    root = Path(__file__).parent
    result = HelloWorldFile.build(
        output_dir=root / "dist",
        format="zip",
        readme_file=root / "README.md",
        citation_file=root / "CITATION.cff",
    )
    return Path(result.archive_path)

context.input["files"] groups file records by data product, such as image. The block prefers relative_path when choosing a filename and falls back to file_uri. It uses only the first file in each item; an item with no files raises an error. Upload one image without a plot label for this first run.

self.models.invoke(...) uses the resolver supplied by the execution host. The block's reusable code therefore needs no server address or API key. raise_for_status() makes an unsuccessful service response fail the call.

6. Test the block and create its ZIP​

Keep the existing main() and if __name__ == "__main__" sections below the code above. The repository's local test connects the model tag to your running service and supplies a filename:

hello_world/hello_world_block.py (local test and entry point)
def main() -> None:
    """Test the block against the local service on port 4000 and build its ZIP.

    Start the Hello World BentoML service before running this file.
    """
    model_tag = "hello_world:latest"
    resolver = HttpModelResolver({model_tag: "http://localhost:4000"})
    try:
        block = HelloWorldFile(model_tag)
        block.models = resolver
        context = BlockContext(
            input={"files": {"image": [{"relative_path": "example.png"}]}}
        )
        greeting = block.call(context)
        assert greeting == "Hello, example.png!", greeting
        print(greeting)
    finally:
        resolver.close()

    print(f"Generated ZIP: {generate_zip()}")


if __name__ == "__main__":
    main()

Run it in the second terminal:

uv run --locked python hello_world/hello_world_block.py

The script asserts that the result is Hello, example.png!, prints that greeting, and prints the generated block ZIP path inside hello_world/dist/. The mock input uses only a filename; no real example.png is needed for this local test. If the assertion or service request fails, packaging is not reached.

generate_zip() includes the example's README and citation file. Edit those files to describe and credit your own method before distributing a variant. You now have a model ZIP and a separate block ZIP.

7. Publish and deploy in PhenoWorks​

An administrator performs the model and module publication steps:

  1. Open Models → Upload model, choose hello_world/hello_world.zip, and complete the upload.
  2. Wait for package validation to finish successfully. If it fails, inspect the validation log before continuing.
  3. Open the package's menu, choose Deploy model, and confirm Deploy. Follow the deployment until it is available; a valid package alone is not a running service.
  4. Open Modules → Publish module and upload the block ZIP printed in step 6.

If you are not an administrator, share the two archives with your platform administrator. Local packaging and testing can be completed before publication.

8. Run the block on a dataset​

  1. In Models, find the deployed Hello World service. Copy its actual model_ref or inspect How to use. The platform reference can look like model-3/hello_world:0.1.0; use the value displayed by your instance.
  2. In Modules, find Hello World and install it in your account.
  3. Create a dataset and upload one RGB image as a single file, using modality rgb and data product image.
  4. In Editor, right-click the dataset and choose Run Analysis. Select Hello World, continue to its parameters, and select the deployed service for model.
  5. Review and start the run, then follow it on Jobs. Check its completion status and log for errors. The block returns Hello, <your filename>! as its step output; this example does not explicitly save a greeting artifact.

The local hello_world:latest mapping belongs to the standalone test. In PhenoWorks, choose the catalog's deployed model reference; PhenoWorks supplies the authenticated resolver. Your local port-4000 service is not the platform deployment and can be stopped with Ctrl+C after local testing.

Troubleshooting and next steps​

SymptomCheck
Port 4000 is already in useStop the Iris service or the earlier Hello World process before serving.
The block cannot connectKeep serve.sh running while executing the local block test.
StopIteration in callSupply an item containing at least one file record.
The module is absent from the pickerPublish and install the rebuilt ZIP with supported_inputs set to ["rgb:image"], then use a dataset with that input pair.
No model can be selectedAsk an administrator to deploy the model and wait for availability.
